# Hartanah MAIS (data awam) — manifest sumber

`hartanah_mais.json` is a curated list of **real, publicly documented** properties of Majlis Agama
Islam Selangor (MAIS), Perbadanan Wakaf Selangor (PWS), Lembaga Zakat Selangor (LZS) and
MAIS-administered religious institutions in Selangor. `php artisan sisdata:mais-seed` turns each one into
a "Profil Hartanah 360°" demo record and fills every module with **synthetic** operational data around it.

Retrieval date for this version: **2026-10-25**. Raw downloads are **not** committed; they are cached in
`storage/app/mais-raw/` (gitignored: `osm/` Overpass responses, `web/` HTML + text extracted from PDFs,
`nominatim/` geocoder responses).

## Attribution (required)

> https://www.openstreetmap.org/copyright

Entries with `"asal": "osm"`, every `geometri.geojson` outline and every coordinate with
`"geocode": "osm"` or `"nominatim"` are a derived database of OpenStreetMap (ODbL 1.0). Any public use
must show the attribution above; if the derived database is distributed publicly it must be offered under ODbL.

News articles and official web pages are used for **facts only** (name, type, location, year, area, rent,
operator organisation, stream), each with its source URL and retrieval date; text is never copied beyond a
short phrase. Official PWS/MAIS documents (rental lists, lease notice 2025, annual report 2024, gazettes)
are public documents.

## Fields — real vs synthetic

| Data | Real (public source) | Synthetic (generated by `sisdata:mais-seed`) |
| --- | --- | --- |
| Property | name, type (`jenis`), address, coordinates, OSM outline, public facts (`fakta`: year, area, rent, operator, status…), stream (`aliran`) **only when a source says so** | — |
| District / mukim | derived: nearest MOD-REF mukim polygon (`ref_sempadan`; mukim polygons are themselves approximate) | — |
| `lot_tanah` | name + facts + sources in `catatan`, `tag` | lot number (`Lot 1xxxxx` / `PT 6xxxx–9xxxx`), area unless public, category, zoning, express condition; `bahagian_pemilik` when `aliran = tidak_dinyatakan` (assumption by type, stated in `catatan`) |
| `data_spatial` | OSM outline (`sumber_data = lakaran`, building footprints widened by 8 m) | rectangle around the public point sized from the public area or the type (`sumber_data = sintetik`) |
| HKM / PER / PJK / CKI / PTN / ADU / KES / TSU / AST / DMS / WFE | — | everything: titles (MAIS as registered owner), vault, encumbrances, acquisition cases, premises, tenants (names end in "(Sintetik)", IC place code `00`), contracts, payments, tax bills, inspections, complaints, court cases, land-office matters, assets, PDFs watermarked CONTOH / SINTETIK, approvals |

Every synthetic row carries the module's `sintetik` flag (or `sumber_rekod = sintetik`); the lot lineage is
`sumber_sistem = mais_awam`, `fail_asal = database/data/mais/hartanah_mais.json`, `kunci_asal = MAIS-nnn`.

## What is NOT here (and why)

- **No personal data**: no waqif (donor) names, officers, tenants, contact persons, phone numbers or e-mail
  addresses — those fields were dropped at collection. Pewakaf rows in MOD-HKM say "nama tidak didedahkan".
- **Real lot / title numbers are not used** as SISDATA lot numbers (a few appear inside the public address
  text of PWS/MAIS documents, e.g. a PT number in a lease notice).
- Gazette lists of waqf lots (Enakmen Wakaf 2015 s.16; 2017/2018 gazettes, 926 lots) were parsed for reference
  but **not** loaded: they have no coordinates and some rows name individual waqif.

## Caveats

- `aliran` is `tidak_dinyatakan` for most mosques, religious schools and cemeteries: MAIS administers mosques and is sole
  trustee of waqf, but no source states the land tenure of that particular site. The seeder then picks a
  `bahagian_pemilik` (mostly wakaf for mosques/schools/cemeteries) and says so in the lot's `catatan`.
- Religious schools (SRA/SAR/KAFA, Maahad Integrasi) are run by JAIS / the state; including them as MAIS-related
  property is a demo assumption. Private tahfiz/pondok schools, courts and federal premises were excluded.
- Coordinates from Nominatim are often street / locality level; estimated parcels (`geometri: anggaran`) may overlap
  neighbouring (synthetic) lots — MOD-PRO then marks the spatial record `bertindih`, which is itself useful demo data.
- Mukim boundaries in MOD-REF are approximate (Voronoi), so a few properties may be assigned to a neighbouring mukim.
- Rent / status facts reflect the source date (PWS lists 2026, MAIS lease notice 2025).

## Legal basis cited in the demo

- Enakmen Wakaf (Negeri Selangor) 2015 [En. 15/2015]: s.4 MAIS sole trustee of all waqf (secondary sources —
  verify against the official text), s.16 gazetted lists of Majlis waqf property (confirmed from the gazettes).
- Enakmen Pentadbiran Agama Islam (Negeri Selangor) 2003 [En. 1/2003]: ss.99–105 mosque administration
  (s.105 exemption gazette 2016).

## Refresh

```bash
php artisan sisdata:mais-seed            # adds the MAIS properties (refuses production; skips if already seeded)
php artisan sisdata:mais-seed --force    # re-run: only missing properties are added
```

The curation scripts (Overpass queries, web extraction, merge + mukim mapping) were run once by the data
track; the dataset is versioned here and edited by hand from now on.
