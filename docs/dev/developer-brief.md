## Common brief for every SISDATA G0 developer

You are one of several developers building SISDATA (MAIS — Majlis Agama Islam Selangor — land/property system) in parallel. The repo is ~/MYDS-Laravel (Laravel 13 JSON API + Next.js 16 in `frontend/`, PostgreSQL 17 + PostGIS). You work in your own git worktree.

### First steps (in your worktree)
1. Sync the main checkout's CURRENT working tree into your worktree (your worktree's git HEAD is stale; git commands against the main checkout are blocked):
   `rsync -a --delete --exclude=.git --exclude=/vendor --exclude=node_modules --exclude=.claude --exclude=/storage --exclude=.next --exclude=.env ~/MYDS-Laravel/ ./`
   Then `cp ~/MYDS-Laravel/.env .env` and in that copy set `REDIS_PREFIX=sisdata_<code>_`, `CACHE_PREFIX=sisdata_<code>_`, `HORIZON_PREFIX=sisdata_<code>_horizon:`, `QUEUE_CONNECTION=sync` (Redis is shared with the lead's running app — never run horizon/queue:work/queue:restart/cache:clear without your prefix), `composer install`, and `npm ci` in `frontend/` (do not symlink node_modules — Turbopack rejects it). Don't rely on `git status`/`git diff` in your worktree to see your changes — list them yourself in the report.
2. Read: `CLAUDE.md` (conventions + gotchas — follow them), `docs/PLAN-SISDATA.md` (your module's slices), your module's section in `docs/srs/SRS-SISDATA.md` (requirements table, process flow, data entities, security controls, reports, acceptance criteria), §4 data model and §5.2 cross-module requirements (SRS-GEN-01..09) in the same file. `docs/srs/requirements.csv` lists every code.
3. Read ALL cross-module contracts: `app/Modules/*/Contracts/**` and `app/Modules/*/Events/**` (RBC: AccessControl, PermissionRegistry, ScopedByAccess, login/status events; AUD: AuditLogger, Auditable; NTF: Notifier, NotificationTypes; DMS: DocumentStore; WFE: WorkflowEngine, WorkflowFlows, WorkflowCompleted; ADM: Parameters, SearchProvider(s)). Each is implemented by its owning module (several are being built right now in parallel by other developers); until then `app/Support/Fallbacks.php` binds a stand-in. Your module must IMPLEMENT its own contracts and bind them in its ServiceProvider, and must USE the others' contracts (declare your permissions via PermissionRegistry, your notification types via NotificationTypes, your parameters via Parameters…). In tests, bind fakes/real implementations as needed. Also read `app/Support/Fallbacks.php`, `app/Support/Modules/ModuleServiceProvider.php`, `app/Modules/Platform` (reference module), `tests/Architecture/ModuleBoundaryTest.php`.

### Rules
- Your code lives in `app/Modules/<YourModule>/` (Models, Http, Services, Policies, Database/migrations, Database/seeders, lang/ms + lang/en, routes.php, Console). Tests in `tests/Modules/<YourModule>/`. Frontend pages under `frontend/app/(dashboard)/admin/<module-code>/…`, module-specific frontend helpers in `frontend/lib/<module-code>.ts`.
- Use another module ONLY through its `Contracts\` or `Events\` namespace (architecture test enforces it). Do not edit another module's folder. If you need a contract that doesn't exist, define it in YOUR module's `Contracts\` and say so in your report.
- Do not edit these shared files: `config/modules.php`, `frontend/components/Sidebar.tsx`, `CLAUDE.md`, `docs/PLAN-SISDATA.md`, `.github/`, `phpunit.xml`. Instead list in your report what the lead should add (e.g. sidebar entries: label, href, permission key). Minimal, necessary edits to `app/Providers/AppServiceProvider.php`, `routes/*.php`, `lang/ms.json`, `frontend/lib/types.ts` are allowed — keep them small and list them.
- Table and column names in Malay snake_case following the SRS entity names (e.g. `peranan`, `peranan_kebenaran`, `audit_rekod`). The existing `users` table stays the user table (Laravel auth) — extend it with migrations instead of creating a parallel `pengguna` table.
- Everything user-visible in Bahasa Malaysia (SRS-GEN-09): API messages via `__()` with module translations (`__('<code>::file.key')`), frontend labels in Malay. MYDS UI: reuse `frontend/components/ui/*` and patterns from Kitchen Sink (`/admin/kitchen-sink`); wrap pages in `<PageContainer>`; mobile-friendly (no horizontal scroll at 375px).
- Every endpoint authorises through `App\Modules\Rbc\Contracts\AccessControl` (Gate / `can:` middleware) — never role-string checks.
- Tests: name each test after the SRS code it proves: `test_SRS_<MOD>_<NN>_<what>` (several tests per code are fine). Cover the module's acceptance criteria ("Kriteria penerimaan") as automated tests where they're code-testable. Test authorisation through the API directly, including a "user without permission / out-of-scope district" case.
- Scope: implement the module's requirements that are buildable in code now. For things needing infrastructure MAIS hasn't given (real SIEM, real SSO directory, SMS gateway…) build an adapter interface + a local/mock implementation. Skip pure procurement/process items and list them. Prefer depth on Wajib (mandatory) items over breadth.
- Local services are native (no Docker): Postgres :5432, Redis :6379, Mailpit SMTP :1025, MinIO :9000, ClamAV socket /opt/homebrew/var/run/clamav/clamd.sock, GeoServer :8085, Keycloak :8180 (realm `mais`). Don't run `brew install`; if you need something not installed, report it.
- DATABASE SAFETY: run tests ONLY against your own test DB: `DB_DATABASE=myds_laravel_test_<yourcode> php artisan test` (it already exists with postgis/vector/pg_trgm). On the shared dev DB `myds_laravel` you may run `php artisan migrate` (forward only) — NEVER `migrate:fresh`, `migrate:refresh`, `migrate:rollback`, `db:wipe`, or tests against it. Other developers share it.
- `php artisan serve` WITHOUT `--no-reload` drops env overrides and silently serves the dev DB. Always: `DB_DATABASE=myds_laravel_test_<code> CACHE_STORE=array SESSION_DRIVER=file QUEUE_CONNECTION=sync php artisan serve --no-reload --port=<port>` and verify which DB it uses.
- Ports 8000/3000 belong to the lead's running servers; if you need servers for a browser check, use another port pair (e.g. 8011/3011) and set FRONTEND_URL / INTERNAL_API_URL accordingly for that run only.
- Do NOT git commit or push. Leave everything uncommitted in your worktree.
- Do NOT run anything against the shared dev DB `myds_laravel` (no migrate, no seed) — it is blocked for developers; the lead migrates it when merging. For browser checks use your own test DB (`DB_DATABASE=myds_laravel_test_<code>` for the server too) after `migrate:fresh --seed` on THAT DB.
- Existing helpers to reuse: `User::factory()->withPermissions([...])->withRole('pegawai_operasi')->withScope('daerah', ['1008'])->status('gantung')->sso()` (MOD-RBC); `tests/Modules/Aud/Concerns/AssertsAuditTrail` (`assertAudited`, `assertFieldChanged`…); `Rbc\Contracts\Concerns\ScopedByAccess` trait + `protected array $accessScopes = ['daerah' => 'kod_daerah', 'mukim' => 'kod_mukim', 'klasifikasi' => 'klasifikasi']` for record scoping; `Dms\Contracts\DocumentStore` + frontend `<DocumentAttachments ownerType ownerId />` (frontend/components/dms) for attachments; `Wfe\Contracts\WorkflowEngine` + listen to `WorkflowCompleted` for approvals (never build approval logic yourself — SRS-GEN-03); `Ntf\Contracts\Notifier` + `Ntf\Contracts\Reminders` for scheduled reminders; `Adm\Contracts\Parameters` for tunables; `Adm\Contracts\SearchProviders` to join global search.
- Reference codes come from MOD-REF (`ref_daerah` 4-digit codes e.g. `1008`, `ref_mukim` 6-digit e.g. `100803`, `ref_jenis_hak_milik`, `ref_kategori_guna_tanah`…, API `/api/v1/ref/*`). Synthetic sample lots/titles/owners are in `staging_lot_tanah`, `staging_hak_milik`, `staging_pemilik` (`php artisan ref:sample-lots`), all flagged `sintetik`. Never store real personal data.
